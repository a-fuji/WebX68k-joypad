# 海賊王ゲームの最小仕様と設計判断

この文書は、X68000上で検証できる最初のゲームの仕様と、その範囲を選んだ理由を記録する。

## ゲームの単位

固定256×256画面、1人プレイ、2ステージとする。ザコを6体倒すとボスが出現する。第1ステージはビッグ・マム風、第2ステージはカイドウ風の自作ドット絵を表示し、2体目を倒すとALL CLEARになる。ボスHPは16/24、撃破得点はザコ100点、ボス1000点。敵の通過、接触、敵弾により残機を失う。

8方向移動、押し続けるショット、押下時だけ発動する全体攻撃の2トリガーを実装する。残機3、各ステージの全体攻撃2回とし、全体攻撃は画面上のザコ・敵弾を消去し、ボスへ8ダメージを与える。援護の絵と文言はゾロ風・サンジ風を交互に出す。ダメージ後は一定時間無敵にし、同じ接触で残機を連続して失わないようにする。

最初の動作確認では敵8体、自弾8発、敵弾8発の固定配列を使う。動的メモリ、画像の逐次ロード、外部音楽ドライバ、セーブデータは扱わない。画面・入力・当たり判定・ボス遷移・再開・終了を、一つの小さい実行ファイルと読み取り可能な状態で確認できることを優先した。

## 表示と音

タイトルは提供画像を256×256へ縮小し、見出し「海賊王ゲーム」と操作案内を加え、256色へ量子化する。Dev68KToolsのGraphics CodecでGMD/PALを生成し、同じパレットから65536色モードのワード列へ展開して実行ファイルに埋め込む。元画像の容量やデコーダーをゲストへ持ち込まずに、添付画像をタイトルとして確認するためである。

ゲームは256×256、16色、GVRAMの2ページを交互に描画・表示する。タイトルの色数とゲームの描画コストを分け、描きかけの画面が見える問題を避ける。ゲームループはIOCS `_ONTIME`の差分で進み、5/100秒より短い間隔では更新しない。遅い環境ではフレームを追いつかせる処理をせず、ゲームが遅くなる。

音楽は自作の短いFMフレーズをIOCS `_OPMSET`でチャンネル7へ送る。常駐ドライバ、タイマー割込み、ベクタ変更、ZMD/ZPDを初版の依存にしない。終了時にはキーオフし、起動前の画面モードとスーパーバイザ状態を復元し、キーバッファを消費してDOSプロンプトに操作キーが残るのを防ぐ。

## XDFと配布境界

FDD0のHuman68kと、FDD1の開発ディスクを分ける。開発用XDFはHDSから読み取ったHAS060・HLK、独自ソース、タイトルデータ、ビルドバッチ、出力ディレクトリだけを含む。MaidLandの参照範囲は`doc/workflow.md`のHAS060/HLK手順、容量・メモリ予算、入力上の注意に限る。ソース・素材をコピーしない。

配布用XDFは新規のFAT12データディスクに、検証済みの`.X`、起動バッチ、操作説明だけを格納する。起動用OSとツールを混ぜないことで、配布ファイルの由来と容量を個別に確認できる。配布ディスク単体の自動ブートは行わず、Human68kを起動したA:と組み合わせてB:のGOを実行する。

XDF全体の生成とファイル格納はホスト側で行う。MCPは装填・画面・入力・読み取りに使い、既知の多クラスタ書き込み問題をビルドの必須経路にしない。タイムスタンプを固定し、同じ入力なら同じXDFを得られるようにする。OS、ツール、提供画像の公開条件が確定するまで、生成物は`_local/`に保存し、外部イメージもGitに追加しない。
