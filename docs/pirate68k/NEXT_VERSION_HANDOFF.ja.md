## 次回、仕様を詰めて取り組む項目

| 項目 | 引き継ぐ意図・確認事項 |
| --- | --- |
| 画像制作 | 背景と通常キャラ32×32・ボス96×96・援護64×64を組み込み済み。追加のアニメーションや作画調整は保存済みPNGと`graphics.py`を基点にする。 |
| 描画と当たり判定 | XSPのハードウェアスプライトを使用。大型化に合わせて当たり判定と配置を調整済み。追加変更時も透明余白・判定・発射位置を併せて確認する。 |
| Z-MUSIC | 常駐ドライバと外部ZMDによる再生へ切替済み。直接OPM操作は撤去。Astra制作曲は[音声手順](AUDIO.ja.md)に従って同名ファイルへ差し替える。 |
| 効果音 | FM8のショット・命中・被弾・必殺技と、ZPDの必殺技・ボス撃破を接続。新規データは音色・トラック形式・PCM番号を合わせる。 |
| 1ドライブ配布 | ユーザーの単体起動できなかったという指摘を解決する候補。単体ブート対応は後続へ残すと合意済み。起動可能なHuman68k環境を基にし、起動領域・必要ファイル・終了後の挙動まで検証する。開発ツール・不要ソースは配布版へ入れない。 |
| 回帰検証 | 初版の8方向・2トリガー、スコア、ボスから次ステージ、ゲームオーバー・再開・終了を維持する。画像と音楽の追加後はメモリ・ディスク容量、ゲーム速度、音のテンポ、配布ディスクでの起動を測る。 |

Z-MUSICの既存実験は[実現可能性資料](../X68K_HDS_ZMUSIC_FEASIBILITY.ja.md)の「ZMP7 と2ドライブ運用」と[検証履歴](../X68K_VERIFICATION_HISTORY.ja.md)を読む。ZMSからZMDをHuman68k上で生成する経路は過去に確認されているが、制作曲のコンパイルとゲーム内確認は別々に行う。既存の音楽データの閲覧・試聴と、ゲームへの素材流用は区別する。

MCPの大容量ファイル書き込み問題は未解決。ホスト側でXDFを一括生成して装填する初版の経路を活用する。画像・音楽追加後も同じ条件で再生成し、配布用マニフェストとSHA-256を更新する。

外部イメージ・ツール本体・元画像を無断でリポジトリへ追加しない。生成XDFはサイズと公開条件を確認し、必要ならRelease等で扱う。リモートへプッシュする前に対象リポジトリと公開範囲を確認する。
