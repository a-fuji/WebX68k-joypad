## 制作状態

| 版 | 内容 | 確認状況 |
| --- | --- | --- |
| v01 / `PAINT_HOOK_V01.ZMS` | 147 BPM、8小節、約13秒 | ユーザーが再生確認。短すぎるとの指摘 |
| v02 / `PAINT_60S_V02.ZMS` | 144 BPM、36小節、60秒。FM打楽器のピッチ・ゲート・強弱とフィルを調整 | ユーザーが試聴。ベース・伴奏が低く、主旋律に余計な音があるとの指摘 |
| v03 / `PAINT_60S_V03.ZMS` | ベースと伴奏3声を12半音上げ、主旋律を137音から101音へ整理 | 静的検証済み。ユーザーによる試聴結果は未受領 |

v03はv02のテンポ・形式・音色パラメータ・ドラムを維持。冒頭に追加していたフィル、すくい上げに相当する経過音、不要な同音の再打鍵を減らし、同じ音の持続を小節越しに接続した。正確な原曲採譜ではなく、旋律が伝わることを優先した近似編曲。

構成は冒頭8小節 → サビ16小節 → 間奏4小節 → サビ後半8小節。冒頭は歌い出しの旋律をインスト化したもので、原曲のギター・シンセによるイントロを忠実に採譜したものではない。間奏も冒頭モチーフを編曲したもの。

| FMチャンネル | パート |
| --- | --- |
| 1 | 主旋律 |
| 2 | ベース |
| 3〜5 | 伴奏3声 |
| 6 | キック |
| 7 | スネア |
| 8 | ハイハット・シンバル |

ユーザー指定によりFM全8チャンネルをBGMで使い、ADPCMは効果音用に確保する。楽曲にADPCMドラムは使わない。音色の出典はローカルのprovenanceファイルを参照。音色素材の再配布条件も独立した確認が必要。

## 確認できたこと・未確認のこと

v03の保存済み検証記録では、全8トラックが6,912 tick（48 PPQ）で一致し、144 BPMで名目60秒。MMLの音符・音価を編曲JSONと比較し、2周分のループで一致を確認している。ベース・伴奏の発音時刻、音色パラメータ、ドラムはv02から変えていない。

OPMでのv03試聴、Z-MUSICコンパイラによる受理、ZMD生成、ゲーム内再生は未確認。静的検証は実機・エミュレータでの聴感や音色の適合を保証しない。v01・v02の再生確認はユーザー報告に基づく。

ユーザー指定の主題歌MP3は未入手。v03では取得済み公式Vocal Stem WAVと既存のピッチ測定結果を参照した。原曲との聴き比べで旋律の完全一致を確認したものではない。YouTube動画から音声を抽出・無断ダウンロードした事実はない。

## 既存ツールと再開時の注意

既存コンバータを新規作成・改修せず、次の実装を再利用した。

| ツール | 保存先 |
| --- | --- |
| MIDI生成 | `/Volumes/AITuberRetroMacDev/Projects/MIDICreator/dist/music/midiWriter.js` の `compositionToMidi` |
| MIDI → MIDI系ZMS | `/Users/m1prime/Projects/ZMSConverter/midi_to_zms.py` |
| MIDI系ZMS → FM用ZMS | 同ディレクトリの `zmconverter.py` |
| ZMS資料・音色 | 同ディレクトリの `ZMUSIC_REFERENCE.md`、`profiles/`、`Sozai/` |

既存ツールは各MIDIチャンネルを単音のFMトラックへ割り当てる。今回の入力は48 PPQ、8単音トラック。初期テンポ・プログラム等を使用し、途中のテンポ変化、ピッチベンドやサステインに依存しない。MIDIの各音ベロシティはFMの強弱へそのまま反映されないため、打楽器の各音の音色・音量指定は制作ZMS側へ追加した。

ループの各トラック先頭に `o3` を置き、2周目以降のオクターブずれを防ぐ。打楽器のコマンド追加後に既存関数 `ensure_track_buffers` でバッファ容量を調整する。この処理を省いて中間ZMSから再変換するだけでは、納品ZMSと一致しない。最終ZMSはCP932で扱える文字とCRLF改行。

再開時は以下の順に進める。

1. 制作ルート、最新ZMS、検証記録、外付けボリューム上のMIDI生成ツールの存在を確認する。別Macなら非公開の引き継ぎZIPを独立した制作フォルダへ展開し、`SHA256SUMS.json` で内容を確認する。WAVは別途保全したものを戻す。
2. 外部ツールは `analysis/tool-hashes-v03.json` のSHA-256と照合する。制作スクリプトは絶対パスを持つため、別環境では制作側のパスを合わせる。既存コンバータ本体は変更しない。
3. まず保存済みv03を試聴し、ベース・伴奏の高さと主旋律の余計な音が改善したか確認する。音の細密分析や全面的な音色設計より、ユーザーの聴感上の指摘を優先する。
4. 修正依頼があれば別名の次版として作る。`build_v03.py` は既存出力を保護して停止するため、v03を消して再実行しない。実際の変換引数は `analysis/build-log-v03.json` を参照する。
5. 音符・音価、全トラックの長さ、2周のループ、8単音チャンネル、ADPCM不使用を検証し、ZMSと試聴用ZIPを渡した時点で停止する。今回の引き継ぎ作業では音楽データを再生成していない。

同じエラーへの実質的に同一の再試行は2回まで。大規模な新規プログラム、環境変更、大量生成、有料サービス利用は事前確認が必要。

## ゲーム組込み前の調整事項

現在の[ゲーム音声手順](../pirate68k/AUDIO.ja.md)はFM8を効果音用としている。この楽曲の「FM8もBGMに使用・効果音はADPCM」という指定とは一致しないため、組込み担当側でチャンネル・効果音の扱いを調整してから差し替える必要がある。本制作ではゲームASM、XSP、XDF、WebX68k/MCPを変更しない。

ゲーム側はZ-MUSIC v2を使用しているが、制作ZMSのコンパイル成功は別途確認する。ZMS承認後に組込み担当へ引き継ぐまでは、ZMD化やディスクイメージへの組込みを進めない。
